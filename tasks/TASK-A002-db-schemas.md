# TASK-A002: Define Database Schemas with SQLModel & Alembic

## 1. Context & Core Goal
The objective of this task is to define the physical database schema for the **User Management** feature using **SQLModel** (which combines SQLAlchemy and Pydantic) and configure database migrations using **Alembic** under **PostgreSQL 16**.

In alignment with **Applying UML and Patterns** (Chapter 26: Association over Generalization) and **Spec-Driven AI Engineering** (Chapter 9.2: Entity Modeling), we are discarding database-level class inheritance in favor of a clean **1:1 Composition/Association** between `User` (Credential/Account) and `Persona` (Identity).

---

## 2. Structural Requirements & Boundaries

### 2.1 Directory Boundaries
You have write permissions **ONLY** within the following directories:
*   `src/infrastructure/db/` (for models, migration configurations, and metadata)
*   `tests/integration/` (for testing the physical database schemas and constraints)
*   `tasks/task-index.md` (to update status)

You are **STRICTLY FORBIDDEN** from modifying files in:
*   `docs/`
*   `agent/`

### 2.2 Physical Entity Design (SQLModel)
You must create three SQLModel entities in `src/infrastructure/db/models.py`:

#### 1. `Persona` (Physical Identity)
*   `id`: `UUID` (Primary Key, default generated by backend/Postgres via `uuid4`)
*   `first_name`: `str` (Required)
*   `last_name`: `str` (Required)
*   `identity_card`: `str` (Required, UNIQUE, indexed). **Must support alphanumeric extensions** (e.g., `"1234567-1B"`).
*   `birth_date`: `date` (Required)
*   `phone`: `str` (Optional)

#### 2. `User` (Security / Authentication Account)
*   `id`: `UUID` (Primary Key, default generated by backend/Postgres via `uuid4`)
*   `email`: `str` (Required, UNIQUE, indexed)
*   `password_hash`: `str` (Required)
*   `role`: `str` (Required, restricted via database/Python validation to ENUM values: `"dev"`, `"admin"`, `"doctor"`, `"patient"`)
*   `created_at`: `datetime` (Required, default `utc_now`)
*   `persona_id`: `UUID` (Foreign Key pointing to `persona.id`, UNIQUE constraint to enforce strict `1:1` association, ON DELETE CASCADE)

#### 3. `Device` (Hardware ID Binding)
*   `id`: `UUID` (Primary Key, default generated by backend/Postgres via `uuid4`)
*   `android_id`: `str` (Required, UNIQUE, indexed)
*   `user_id`: `UUID` (Foreign Key pointing to `user.id`, ON DELETE CASCADE)
*   `linked_at`: `datetime` (Required, default `utc_now`)

## 3. Alembic Configuration (Strict Guardrail)
To prevent hardcoded credentials or environment mismatches (Spec-Driven AI Engineering, Chapter 23.6):
1.  **Dynamic Connection:** Modify `alembic/env.py` to import and load the active database connection string (`DATABASE_URL`) from your Pydantic settings (`src/core/config.py`).
2.  **Target Metadata:** Set `target_metadata = SQLModel.metadata` in `alembic/env.py` so Alembic can detect all SQLModel schemas automatically.
3.  **Command Execution:** Generate the initial migration script and verify it outputs correct SQL statements for constraints, unique indices, and foreign keys.

## 4. Acceptance Criteria (BDD/Gherkin)

```gherkin
Feature: Database Schema & Migration Verification

  Scenario: Run migrations on PostgreSQL container
    Given a fresh, running PostgreSQL 16 container in Docker
    When Alembic migration commands "alembic upgrade head" are executed
    Then all tables ("persona", "user", "device") must be successfully created with correct data types
    And the schema must match SQLModel entity metadata

  Scenario: Enforce uniqueness constraints
    Given a PostgreSQL database with a created Persona "1234567-1B"
    When an agent tries to insert another Persona with the same "identity_card" "1234567-1B"
    Then the database must raise an IntegrityError (UniqueConstraintViolation)
    And no duplicate records must be persisted

  Scenario: Clean hardware release on user deletion
    Given a registered User with persona and a bound Device with "android_id" "device_xyz_999"
    When the User record is physically deleted from the database
    Then the corresponding Device record must be automatically cascades-deleted
    And the "android_id" "device_xyz_999" must be completely free and ready for future registrations
```
